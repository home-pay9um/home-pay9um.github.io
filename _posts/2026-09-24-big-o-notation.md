## 1. Big-O 표기법이란?

빅오 표기법(Big-O Notation)은 **입력 크기 `n`이 증가할 때 알고리즘의 연산량이 어떻게 증가하는지**를 나타내는 방법이다.

실제 실행 시간은 컴퓨터의 성능이나 실행 환경에 따라 달라질 수 있기 때문에, 알고리즘의 성능을 비교할 때는 입력 크기에 따른 **성장률**을 중심으로 분석한다.

Big-O 표기법에서는 대표적으로 다음과 같은 복잡도를 사용한다.

![Big-O Notaion](big-o-notation.png)

| **Big-O** | **이름** | **특징** |
| :--- | :--- | :--- |
| $O(1)$ | 상수 시간 | 입력 크기와 관계없이 일정 |
| $O(\log n)$ | 로그 시간 | 입력 크기가 증가해도 매우 느리게 증가 |
| $O(n)$ | 선형 시간 | 입력 크기에 비례하여 증가 |
| $O(n \log n)$ | 선형 로그 시간 | 선형 시간보다 빠르게 증가 |
| $O(n^2)$ | 제곱 시간 | 입력 크기의 제곱에 비례하여 증가 |
| $O(2^n)$ | 지수 시간 | 입력 크기가 증가할수록 매우 빠르게 증가 |

---

## 2. $O(1)$ - 상수 시간

`$O(1)$`은 **입력 크기와 관계없이 일정한 시간이 걸리는 경우**를 의미한다.

입력의 크기가 커지더라도 수행해야 하는 작업의 횟수가 크게 변하지 않는다.

> 입력 크기와 관계없이 일정한 수준의 작업만 수행한다.

대표적인 특징:
* 가장 일정한 증가율을 가진다.
* 입력 크기가 커져도 실행 시간의 증가가 거의 없다.
* 매우 효율적인 복잡도로 볼 수 있다.

---

## 3. $O(\log n)$ - 로그 시간

`$O(\log n)$`은 **입력 크기가 증가하더라도 필요한 작업의 수가 매우 느리게 증가하는 경우**를 의미한다.

입력의 범위를 한 번에 크게 줄여가며 처리하는 알고리즘에서 주로 나타난다.

> 입력 크기가 커져도 작업 횟수가 천천히 증가한다.

대표적인 특징:
* `$O(1)$` 다음으로 증가율이 낮다.
* 큰 입력을 다루는 데 비교적 유리하다.
* 입력 범위를 반복적으로 줄이는 방식에서 나타난다.

---

## 4. $O(n)$ - 선형 시간

`$O(n)$`은 **입력 크기에 비례하여 작업량이 증가하는 경우**를 의미한다.

입력의 크기가 2배가 되면 필요한 작업량도 대체로 2배 정도 증가한다.

> 입력 크기가 증가하는 만큼 작업량도 함께 증가한다.

대표적인 특징:
* 입력 전체를 한 번씩 확인하는 경우 자주 나타난다.
* 입력 크기와 작업량의 증가가 비례한다.
* 가장 대표적인 기본 복잡도 중 하나이다.

---

## 5. $O(n \log n)$ - 선형 로그 시간

`$O(n \log n)$`은 **선형 시간과 로그 시간이 결합된 형태의 복잡도**이다.

선형보다 빠르게 증가하지만 제곱보다는 느리게 증가한다

> 입력 크기가 증가할수록 작업량도 증가하지만, 제곱 형태로 증가하지는 않는다.

대표적인 특징:
* 효율적인 정렬 알고리즘에서 자주 나타난다.
* 많은 데이터를 처리할 때 비교적 효율적이다.
* `$O(n)$`과 `$O(n^2)$` 사이의 성장률을 가진다.

---

## 6. $O(n^2)$ - 제곱 시간

`$O(n^2)$`은 **입력 크기의 제곱에 비례하여 작업량이 증가하는 경우**를 의미한다.

입력 크기가 2배가 되면 작업량은 대략 4배로 증가한다.

> 입력 크기가 증가할수록 작업량이 빠르게 증가한다.

대표적인 특징:
* 중첩된 반복 작업에서 자주 나타난다.
* 입력이 작을 때는 문제가 크지 않을 수 있다.
* 입력 크기가 커질수록 실행 시간의 증가가 크게 나타난다.

---

## 7. $O(2^n)$ - 지수 시간

`$O(2^n)$`은 **입력 크기가 증가할수록 작업량이 매우 빠르게 증가하는 경우**를 의미한다.

입력 크기가 조금만 증가해도 필요한 작업량이 크게 증가할 수 있다.

> 입력 크기가 증가할수록 작업량이 폭발적으로 증가한다.

대표적인 특징:
* 입력 크기가 커질수록 실행 시간이 급격하게 증가한다.
* 큰 입력을 처리하기에는 비효율적일 수 있다.
* 경우의 수를 모두 확인하는 문제 등에서 나타날 수 있다.

---

## 8. 대표적인 Big-O 비교

![Big-O Ranking](big-o-ranking.png)

위쪽에 있을수록 입력 크기가 증가할 때 작업량의 증가가 작고, 아래쪽으로 갈수록 증가율이 커진다.

특히 `$O(n^2)$`과 `$O(2^n)$`은 입력 크기가 커질수록 작업량이 빠르게 증가하므로, 큰 입력을 처리할 때 성능에 큰 영향을 줄 수 있다.

## 9. 핵심 정리

| **Big-O** | **핵심 내용** | **사용 예시** |
| :--- | :--- | :--- |
| $O(1)$ | 입력 크기와 관계없이 일정 | 배열의 특정 인덱스에 바로 접근할 때 |
| $O(\log n)$ | 입력이 증가해도 작업량이 천천히 증가 | 이진 탐색처럼 탐색 범위를 절반씩 줄일 때 |
| $O(n)$ | 입력 크기에 비례하여 증가 | 반복문으로 데이터를 한 번 순회할 때 |
| $O(n \log n)$ | 선형보다 빠르게 증가하지만 제곱보다는 느림 | 효율적인 정렬 알고리즘을 사용할 때 |
| $O(n^2)$ | 입력 크기의 제곱에 비례하여 증가 | 중첩 반복문을 사용할 때 |
| $O(2^n)$ | 입력 크기에 따라 매우 빠르게 증가 | 모든 경우의 수를 재귀적으로 탐색할 때 |

Big-O 표기법은 알고리즘의 **실제 실행 시간을 나타내는 값이 아니라, 입력 크기가 증가할 때 필요한 연산량의 증가율을 표현하는 방법**​이다.

따라서 알고리즘을 비교할 때는 단순히 현재 입력에서 얼마나 빠른지를 보는 것이 아니라, **입력 크기가 커졌을 때 성능이 어떻게 변하는지**를 함께 고려해야 한다.
