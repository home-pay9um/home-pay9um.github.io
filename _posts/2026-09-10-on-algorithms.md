앞선 [**자료구조와 알고리즘의 개념 정리**](../data-structure-and-algorithm/)에서는 자료구조와 알고리즘이 무엇인지 간단하게 살펴보았다면, 이번에는 **알고리즘에 대한 기본 조건을 중심으로 조금 더 구체적으로 정리**를 한다.

## 1. 알고리즘이란?

**알고리즘(Algorithm)**은 주어진 문제를 해결하기 위해 필요한 **절차와 방법을 명확하게 정의한 유한한 명령의 집합**이다.

일반적으로 알고리즘은 입력된 데이터를 일정한 절차에 따라 처리하여 원하는 결과를 생성한다.

![라이트 모드 전용](algorithm-light.png){: .light }
![다크 모드 전용](algorithm-dark.png){: .dark }

컴퓨터는 문제의 의도를 스스로 판단하여 해결하는 것이 아니라, **정해진 규칙과 절차에 따라 연산을 수행한다.**

예를 들어 사람에게 `"여러 숫자 중에서 가장 큰 숫자를 찾아줘."`라고 말하면 간단한 문제처럼 느껴진다.

하지만 컴퓨터가 이 문제를 해결하기 위해서는 다음과 같은 **구체적인 절차**가 필요하다.

1. 첫 번째 값을 최댓값으로 설정한다.
2. 다음 값을 현재 최댓값과 비교한다.
3. 더 큰 값이라면 최댓값을 변경한다.
4. 모든 값을 확인할 때까지 반복한다.
5. 최댓값을 출력한다.

이 과정은 입력된 정수들을 정해진 규칙에 따라 처리하고 하나의 결과를 만들어 내므로 알고리즘의 예가 된다.

```python
def find_max(data: list[int]) -> int:
    largest: int = data[0]  # 첫 원소를 최댓값으로 설정
    for x in data:          # 모든 원소를 차례로 반복하며
        if x > largest:       # 더 큰 값을 만나면
            largest = x         # 최댓값 갱신
    return largest          # 최댓값 반환
```

이 프로그램은 입력(List)을 받아, 정의된 단계를 유한 번 수행하고, 출력(최댓값)을 내놓는다.

이처럼 추상적인 아이디어가 알고리즘이고, 이 알고리즘을 프로그래밍 언어로 옮긴 것이 프로그램이다.

## 2. 알고리즘의 다섯 가지 조건

알고리즘은 단순히 문제를 해결하기 위한 절차라고 해서 모두 알고리즘으로 인정되는 것은 아니다.

일반적으로 알고리즘은 다음과 같은 **다섯 가지 기본 조건**을 만족해야 한다.

| **조건** | **핵심 내용** |
| :--- | :--- |
| **입력(Input)** | 0개 이상의 입력이 주어질 수 있다. |
| **출력(Output)** | 하나 이상의 결과를 생성해야 한다. |
| **명확성(Definiteness)** | 각 단계가 모호하지 않고 명확해야 한다. |
| **유한성(Finiteness)** | 유한한 단계가 수행된 후 종료되어야 한다. |
| **효과성(Effectiveness)** | 각 단계가 실제로 수행 가능한 명령으로 구성되어야 한다. |

### 입력(Input)

알고리즘은 0개 이상의 입력(Input)을 받을 수 있다.

입력은 알고리즘이 문제를 해결하기 위해 사용하는 데이터이며, 외부에서 주어지거나 외부 입력 없이 미리 정해진 값을 사용하는 경우도 있다.

따라서 알고리즘에서 입력은 **반드시 하나 이상 존재해야 하는 것이 아니라 0개 이상 존재할 수 있다.**

### 출력(Output)

알고리즘은 실행 결과를 **하나 이상의 출력(Output)**을 생성해야 한다.

출력은 알고리즘이 문제를 해결한 결과이며, 계산된 값이나 처리된 데이터 등이 될 수 있다.

앞에서 살펴본 최댓값을 찾는 알고리즘에서는 입력된 여러 정수 중 가장 큰 값이 최종 출력이 된다.

입력을 받아 처리하는 과정만 존재하고 최종적인 결과를 정의하지 않는다면, 문제 해결 절차로서 알고리즘의 목적을 완전히 충족했다고 보기 어렵다.

### 명확성(Definiteness)

알고리즘의 각 단계는 **누가 수행하더라도 동일하게 해석할 수 있도록 명확하게 정의**되어야 한다.

명확하지 않은 절차
1. 적당히 큰 값을 선택한다.
2. 값을 적절하게 변경한다.
3. 결과가 좋으면 종료한다.

`적당히`, `적절하게`, `좋으면`과 같은 표현은 구체적인 기준이 없기 때문에 수행하는 사람에 따라 결과가 달라질 수 있다.

반면 다음과 같이 조건과 동작을 구체적으로 정의하면 각 단계가 명확해진다.

1. 첫 번째 값을 최댓값으로 설정한다.
2. 다음 값을 최댓값과 비교한다.
3. 현재 값이 더 크다면 최댓값을 현재 값으로 변경한다.

따라서 알고리즘의 각 단계는 **모호한 표현을 배제하고 구체적인 규칙과 절차로 정의**되어야 한다.

### 유한성(Finiteness)

알고리즘은 **유한한 단계가 수행된 후 반드시 종료**되어야 한다.

문제를 해결하기 위해 알고리즘을 실행했는데 절차가 무한히 반복된다면 원하는 결과를 얻을 수 없다.

따라서 알고리즘은 문제를 해결하기 위한 충분한 절차를 수행한 뒤 **반드시 종료할 수 있어야 한다.**

### 효과성(Effectiveness)

알고리즘의 각 단계는 **실제로 수행할 수 있는 명령이나 연산**으로 구성되어야 한다.

아무리 논리적으로 그럴듯한 절차라도 실제로 실행할 방법이 없다면 알고리즘으로 사용할 수 없다.

예를 들어 다음과 같은 단계는 구체적인 실행 방법을 제시하지 않는다.

1. 가장 좋은 방법을 선택한다.
2. 완벽한 결과를 계산한다.

반면 다음과 같이 실제 연산으로 표현할 수 있다.

1. 두 값을 비교한다.
2. 더 큰 값을 변수에 저장한다.
3. 다음 데이터를 확인한다.

효과성은 알고리즘의 각 단계가 **실제로 실행 가능한 기본적인 연산으로 구성되어 있는가**를 의미한다.

### 다섯 가지 조건 정리

> 입력(Input) → 명확하게 정의된 절차 → 실제로 수행 가능한 연산 → 유한한 단계 수행 → 출력(Output)

| **조건** | **확인해야 할 내용** |
| :--- | :--- |
| **입력** | 처리할 데이터가 0개 이상 주어지는가? |
| **출력** | 문제를 해결한 결과를 생성하는가? |
| **명확성** | 각 단계가 모호하지 않은가? |
| **유한성** | 정해진 단계 후 종료되는가? |
| **효과성** | 각 단계가 실제로 수행 가능한가? |

이 다섯 가지 조건은 **알고리즘이 성립하기 위한 기본적인 특성**이다.

## 3. 좋은 알고리즘의 조건

앞에서 살펴본 다섯 가지 조건은 알고리즘이 갖추어야 할 **기본적인 성립 조건**이다.

하지만 이러한 기본 조건을 만족한다고 해서 반드시 좋은 알고리즘이라고 할 수 있는 것은 아니다.

하나의 문제를 해결하는 방법은 여러 가지가 존재할 수 있기 때문에, 실제 알고리즘을 설계하고 선택할 때는 **정확성, 효율성, 명료성** 등을 함께 고려해야 한다.

### 정확성(Correctness)

좋은 알고리즘은 주어진 문제를 **정확하게 해결하고 올바른 결과를 생성**해야 한다.

아무리 실행 속도가 빠르거나 구조가 단순하더라도 잘못된 결과를 생성한다면 문제 해결을 위한 알고리즘으로 적절하지 않다.

따라서 알고리즘을 평가할 때 가장 먼저 확인해야 하는 것은 **문제의 요구사항을 올바르게 해결하는가**이다.

### 효율성(Efficiency)

같은 문제를 해결하더라도 알고리즘에 따라 필요한 **시간과 자원**이 달라질 수 있다.

좋은 알고리즘은 불필요한 연산이나 자원 사용을 줄이고, 주어진 문제를 효율적으로 처리할 수 있어야 한다.

대표적으로 다음과 같은 측면을 고려할 수 있다.

* **시간 효율성:** 문제를 해결하는 데 필요한 연산이나 실행 시간
* **공간 효율성:** 문제를 해결하는 과정에서 사용하는 메모리

예를 들어 같은 결과를 얻을 수 있는 두 알고리즘이 있다면, 불필요한 연산을 적게 수행하거나 더 적은 메모리를 사용하는 알고리즘을 고려할 수 있다.

다만 알고리즘의 효율성을 **정량적으로 비교하는 방법**은 이후 시간 복잡도와 Big-O 표기법에서 별도로 다룬다.

### 명료성(Clarity)

좋은 알고리즘은 **이해하고 분석하기 쉬운 형태**로 작성되어야 한다.

알고리즘의 동작 과정이 명확하게 표현되어 있다면 다음과 같은 작업을 수행하기 쉽다.

* 알고리즘의 동작 과정 확인
* 오류 발생 원인 분석
* 알고리즘의 수정
* 다른 개발자와의 공유 및 유지보수

특히 알고리즘은 실제 프로그램으로 구현하기 전에 문제 해결 방법을 설계하는 단계에서 사용되므로, **각 단계의 의미와 목적을 명확하게 표현하는 것**이 중요하다.

### 일반성(Generality)

좋은 알고리즘은 **특정한 하나의 입력에만 적용되는 것이 아니라 다양한 입력에 대해 동일한 문제를 해결할 수 있어야 한다.**

예를 들어 다음과 같은 알고리즘이 있다면

> `[10, 20, 30]`에서 가장 큰 값을 찾는다.

이것만을 처리하도록 만들어진 절차보다는

> 주어진 정수 목록(List)에서 가장 큰 값을 찾는다.

와 같이 입력 범위를 일반화한 알고리즘이 더 넓은 상황에서 사용할 수 있다.

따라서 알고리즘을 설계할 때는 특정한 사례에만 맞추기보다는 **문제의 본질적인 조건을 기준으로 일반화하는 것**이 중요하다.

## 4. 알고리즘의 기본 조건과 좋은 알고리즘의 차이

앞의 내용을 보면 [**알고리즘의 다섯 가지 조건**](#2-알고리즘의-다섯-가지-조건)과 [**좋은 알고리즘의 조건**](#3-좋은-알고리즘의-조건)은 비슷하게 느껴질 수 있다.

하지만 두 개념은 구분해서 이해를 할 필요가 있다.

| 구분 | 목적 | 주요 내용 |
| :--- | :--- | :--- |
| 다섯 가지 조건 | 알고리즘의 기본적인 성립 조건 | 입력, 출력, 명확성, 유한성, 효과성 |
| 좋은 알고리즘의 조건 | 알고리즘의 품질을 판단하는 기준 | 정확성, 효율성, 명료성, 일반성 |

즉,

> **다섯 가지 조건은 알고리즘이 성립하기 위해 갖추어야 할 기본적인 조건**이고, **좋은 알고리즘의 조건은 여러 알고리즘 중 더 나은 해결 방법을 판단하기 위한 기준**이다.

이 둘을 구분하면 알고리즘의 개념을 보다 명확하게 이해할 수 있다.

## 5. 핵심 정리

알고리즘은 문제를 해결하기 위한 **명확하고 유한한 절차의 집합**이다.

알고리즘이 성립하기 위해서는 다섯 가지 조건을 만족해야 한다.
: 입력, 출력, 명확성, 유한성, 효과성

그리고 실제로 좋은 알고리즘을 설계하기 위해서는 다음과 같은 요소를 함께 고려해야 한다.
: 정확성, 효율성, 명료성, 일반성

결국 좋은 알고리즘은 **문제를 정확하게 해결하면서도, 불필요한 자원 사용을 줄이고, 이해하기 쉬우며, 다양한 입력에 적용할 수 있는 해결 절차**​라고 정리할 수 있다.

이후에는 알고리즘의 효율성을 객관적으로 비교하기 위해 [**시간 복잡도와 공간 복잡도**](../time-complexity-and-space-complexity/), [**Big-O 표기법**](../big-o-notation/)​을 살펴본다.
