알고리즘의 효율성을 판단하기 위해서는 알고리즘이 문제를 해결하는 과정에서 **얼마나 많은 연산을 수행하고, 얼마나 많은 메모리를 사용하는지** 분석할 필요가 있다.

알고리즘의 성능을 분석하는 대표적인 기준인 **시간 복잡도(Time Complexity)**와 **공간 복잡도(Space Complexity)**를 알아보자.

## 1. 복잡도란?

**복잡도(Complexity)**는 알고리즘이 문제를 해결하는 데 필요한 컴퓨터 자원이 입력 크기에 따라 어떻게 증가하는지를 나타내는 개념이다.

알고리즘의 성능을 분석할 때 대표적으로 다음 두 가지 자원을 고려한다.

| **구분** | **의미** | **분석 대상** |
| :--- | :--- | :--- |
| 시간 복잡도 | 알고리즘 수행에 필요한 연산량 | 실행 시간에 영향을 주는 연산 횟수 |
| 공간 복잡도 | 알고리즘 수행에 필요한 메모리 사용량 | 실행 과정에서 필요한 메모리 |

여기서 중요한 기준은 **입력 크기(Input Size)**이다.

같은 알고리즘이라도 처리해야 하는 데이터의 양이 증가하면 필요한 연산이나 메모리도 달라질 수 있다.

따라서 복잡도 분석에서는 단순히 특정 환경에서 실제 실행 시간이 몇 초인지 측정하기보다, `입력 크기가 증가할 때 알고리즘이 필요로 하는 자원이 어떻게 증가하는가?`를 분석한다.

---

## 2. 시간 복잡도

**시간 복잡도(Time Complexity)**는 알고리즘이 문제를 해결하기 위해 수행하는 **연산량의 증가 정도**를 나타내는 개념이다.

여기서 말하는 시간은 실제 시계로 측정한 실행 시간이 아니라, 일반적으로 **입력 크기에 따른 기본 연산의 횟수**를 기준으로 분석한다.

실제 실행 시간은 다음과 같은 환경에 따라 달라질 수 있다.

* CPU 성능
* 메모리 성능
* 프로그래밍 언어
* 컴파일러 및 인터프리터
* 운영체제
* 실행 환경

아래 코드를 예로 들면 `number`의 값이 커질수록 반복문이 실행되는 횟수도 증가한다.

```python
def total(number):
    s = 0
    for num in range(1, number + 1):
        s += num
    return s

print(total(100))           # 반복문 100회 반복
print(total(100_000))       # 반복문 100,000회 반복
print(total(100_000_000))   # 반복문 100,000,000회 반복
```

이처럼 시간 복잡도는 **입력 데이터의 크기가 증가할 때 필요한 연산량이 어떻게 증가하는지**를 분석하는 데 사용한다.

### 실제 실행 시간과 시간 복잡도의 차이

시간 복잡도와 실제 실행 시간은 구분할 필요가 있다.

예를 들어 알고리즘 A가 특정 컴퓨터에서는 1초, 알고리즘 B는 2초가 걸렸다고 해서 항상 A가 더 효율적인 알고리즘이라고 판단할 수 있는 것은 아니다.

실행 시간은 하드웨어와 실행 환경에 영향을 받기 때문이다.

반면 시간 복잡도는 입력 크기와 연산량의 관계를 중심으로 알고리즘의 성능을 분석한다.

실제 실행 시간
: 특정 환경에서 얼마나 오래 실행되는가?

시간 복잡도
: 입력 크기가 증가할 때 연산량이 어떻게 증가하는가?

따라서 서로 다른 환경에서 알고리즘의 성능을 비교하거나 입력 크기가 매우 커지는 상황을 분석할 때 시간 복잡도가 중요한 기준이 된다.

## 3. 공간 복잡도

**공간 복잡도(Space Complexity)**는 알고리즘이 문제를 해결하는 과정에서 필요한 **메모리 사용량의 증가 정도**를 나타내는 개념이다.

알고리즘을 실행하면 입력 데이터뿐만 아니라 변수, 임시 데이터, 자료구조 등을 저장하기 위한 추가적인 메모리가 필요할 수 있다.

다음과 같은 코드를 예로 들어보자.

```python
import sys

def as_list(number):
    result = []
    for num in range(1, number + 1):
        result.append(num)
    return result

print(sys.getsizeof(as_list(10)))
print(sys.getsizeof(as_list(1_000)))
print(sys.getsizeof(as_list(100_000)))
```

이처럼 공간 복잡도는 **입력 크기가 증가할 때 알고리즘이 사용하는 메모리가 어떻게 증가하는지**를 분석한다.

### 공간 복잡도에서 고려하는 메모리

알고리즘의 메모리 사용량을 분석할 때는 단순히 입력 데이터만 보는 것이 아니라 알고리즘이 실행되는 과정에서 추가로 사용하는 공간도 고려해야 한다.

대표적으로 다음과 같은 공간이 있다.

| **구분** | **설명** |
| :--- | :--- |
| 입력 공간 | 입력 데이터를 저장하기 위해 필요한 공간 |
| 보조 공간 | 알고리즘이 실행되는 동안 추가로 사용하는 공간 |
| 변수 | 계산 과정에서 사용하는 변수 |
| 임시 저장 공간 | 중간 결과 등을 저장하기 위한 공간 |
| 호출 스택 | 함수 호출 과정에서 필요한 공간 |

특히 알고리즘의 공간 효율성을 비교할 때는 보조 공간(Auxiliary Space)을 별도로 살펴보는 경우가 많다.

---

## 4. 시간 복잡도와 공간 복잡도의 관계

시간 복잡도와 공간 복잡도는 서로 다른 자원을 측정하지만, 알고리즘의 효율성을 분석한다는 공통점이 있다.

> 시간 복잡도 - 연산량 - 얼마나 많은 연산이 필요한가?
>
> 공간 복잡도 - 메모리 - 얼마나 많은 공간이 필요한가?

두 복잡도는 항상 독립적으로 최적화되는 것은 아니다.

경우에 따라 더 많은 메모리를 사용하여 반복적인 계산을 줄일 수 있고, 반대로 메모리 사용을 줄이기 위해 추가적인 연산을 수행할 수도 있다.

이처럼 시간과 공간은 한쪽의 사용량을 줄이는 대신 다른 쪽의 사용량이 증가할 수 있는 **상충 관계**를 가질 수 있으며, 이를 **시간-공간 트레이드오프(Time-Space Trade-off)**라고 한다.

따라서 알고리즘의 효율성을 판단할 때는 시간 복잡도 하나만 보는 것이 아니라 문제의 특성과 실행 환경에 따라 시간과 공간을 함께 고려해야 한다.

---

## 5. 복잡도 분석의 필요성

알고리즘은 입력 데이터가 작을 때에는 성능 차이가 크게 나타나지 않을 수 있다.

하지만 데이터의 크기가 커지면 알고리즘의 연산량과 메모리 사용량 차이가 크게 나타날 수 있다.

예를 들어 동일한 문제를 해결하는 두 알고리즘이 있다고 하자.

알고리즘 A
: 데이터가 증가해도 연산량이 비교적 완만하게 증가

알고리즘 B
: 데이터가 증가할수록 연산량이 빠르게 증가

작은 데이터에서는 두 알고리즘의 차이가 크지 않을 수 있지만, 입력 크기가 커지면 성능 차이가 크게 발생할 수 있다.

따라서 알고리즘을 설계하고 비교할 때는 단순히 **"정답을 구할 수 있는가?"**​만 확인하는 것이 아니라,

* 얼마나 많은 연산이 필요한가?
* 얼마나 많은 메모리가 필요한가?
* 입력 크기가 증가하면 성능이 어떻게 변하는가?

를 함께 고려해야 한다.

## 6. 핵심 정리

| **구분** | **시간 복잡도** | **공간 복잡도** |
| :--- | :--- | :--- |
| 분석 대상 | 연산량 | 메모리 사용량 |
| 주요 기준 | 입력 크기에 따른 연산량 변화 | 입력 크기에 따른 메모리 변화 |
| 목적 | 실행 효율 분석 | 메모리 효율 분석 |
| 대표적인 자원 | CPU 연산 | 메모리 |
| 분석 결과 | 연산량의 증가율 | 메모리 사용량의 증가율 |

* **시간 복잡도:** 알고리즘의 연산량을 분석한다.
* **공간 복잡도:** 알고리즘의 메모리 사용량을 분석한다.
* 두 복잡도 모두 **입력 크기와 자원의 관계**를 기준으로 분석한다.
* 실제 실행 시간이나 메모리 사용량도 중요하지만, 알고리즘의 일반적인 성능을 분석할 때는 **입력 크기가 증가함에 따라 필요한 자원이 어떻게 변화하는지**가 중요하다.
* 구체적인 복잡도의 표현과 비교에는 **Big-O 표기법**을 사용할 수 있다.

> **시간 복잡도는 알고리즘이 얼마나 많은 연산을 수행하는지를 분석하고, 공간 복잡도는 알고리즘이 얼마나 많은 메모리를 사용하는지를 분석한다.**

두 복잡도 모두 **입력 크기가 증가할 때 필요한 자원이 어떻게 변화하는지**를 분석한다는 공통점을 가진다.
